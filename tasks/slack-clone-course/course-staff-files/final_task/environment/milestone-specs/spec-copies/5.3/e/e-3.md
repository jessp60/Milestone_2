# E.3: IRC while a node is killed

Check: `bash /spec/e/checks/check_e_3.sh`. The rule numbers below match its output.
This check kills the node on port 8001 with `SIGKILL`.

All routes are under `/api/...`, return JSON, and take `Authorization: Bearer <token>`. The three HTTP nodes listen on `127.0.0.1:8000`, `:8001` and `:8002`. Status codes unless a rule says otherwise: `200` on read/update success, `201` on create, `400` on validation, `401` on missing or invalid auth, `403` on auth-but-forbidden, `404` on unknown id, `409` on conflict, `413` on upload over limit, `423` on writes to an archived channel. Every request must answer within 5 seconds.

Important: the checks stop a process with `SIGKILL` by the PID that owns its port. Run each node as its own process that listens on exactly one of the ports `8000`, `8001`, `8002` (not one process that holds all three), so that killing one leaves the other two running. Never stop processes by name (`pkill -f`, `killall`, `pgrep -f`).

Do not start this spec until `check_e_2.sh` passes.

## Uses

The IRC gateway from E.2. Each HTTP node must be its own process, and `/app/start.sh` (or a watcher it starts) must start a dead node again within 15 seconds.

## Adds

| Function | What it does |
|---|---|
| bridge across nodes | IRC clients keep sending and receiving while one HTTP node is down |

## Rules

This is where the grading contract's IRC requirement for a killed node is checked: the other two nodes must still bridge to IRC.

3.1 **Before the kill.** A web post on node 2 reaches a joined IRC client.

3.2 **After the kill, node 0.** After `SIGKILL` of the node on port 8001, a web post on node 0 reaches the IRC client within 3 seconds.

3.3 **After the kill, node 2.** A web post on node 2 reaches the IRC client too.

3.4 **The connection survives.** The IRC connection stays open and answers `PING`.

3.5 **IRC to web.** A `PRIVMSG` sent from the IRC client while node 1 is down shows in the listing on nodes 0 and 2.

3.6 **Dense ids.** Web and IRC writers keep one consecutive `event_id` stream across the kill.

3.7 **New logins.** A new IRC client can register while node 1 is down.
