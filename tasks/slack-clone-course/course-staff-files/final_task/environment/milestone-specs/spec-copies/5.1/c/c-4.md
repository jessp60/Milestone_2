# C.4: slash commands

Routes covered: `POST /api/channels/{id}/messages` when `body` starts with `/`.
Check: `bash /spec/c/checks/check_c_4.sh`. The rule numbers below match its output.

Do not start this spec until `check_c_3.sh` passes.

All routes are under `/api/...`, return JSON, and take `Authorization: Bearer <token>`. The three HTTP nodes listen on `127.0.0.1:8000`, `:8001` and `:8002`. Status codes unless a rule says otherwise: `200` on read/update success, `201` on create, `400` on validation, `401` on missing or invalid auth, `403` on auth-but-forbidden, `404` on unknown id, `409` on conflict, `413` on upload over limit, `423` on writes to an archived channel. Every request must answer within 5 seconds.

## Uses

Users, workspaces, channels (topic, archive, private channels and invitations to a channel), and `POST /api/channels/{id}/messages`.

## Adds

| Function | What it does |
|---|---|
| slash parser | turns a body that starts with `/` into a command or a literal |

## Rules

Commands are posted as `body` strings through `POST /api/channels/{id}/messages`. A side-effect command returns `201` with `{message:null, ...}` and posts nothing to the channel.

4.1 **/me.** Body `/me waves` returns `201` and a normal `message` whose `body` is exactly `/me waves` (kept as typed, not stripped or italicised).

4.2 **/me without text.** Body `/me` returns `400`. So does `/me ` with only spaces after it.

4.3 **/shrug with text.** Body `/shrug oh well` returns `201` and a normal `message` whose `body` is `oh well ¯\_(ツ)_/¯`: the text, one space, then the emoticon.

4.4 **/shrug alone.** Body `/shrug` returns `201` and a normal `message` whose `body` is just `¯\_(ツ)_/¯`.

4.5 **Unknown command.** Body `/nosuchcommand x` returns `400` and posts nothing.

4.6 **Literal slash.** Body `//literal` returns `201` and a normal `message` whose `body` is `//literal`.

4.7 **/topic.** Body `/topic New topic` returns `201` with `message` null and `channel.topic` equal to `New topic`. A later `GET` of the channel shows the same topic.

4.8 **/invite.** In a private channel, body `/invite @<username>` of a workspace member who is not in the channel returns `201` with `message` null and `invited_user.id` equal to that user's id. That user can then read the channel.

4.9 **/invite unknown user.** Body `/invite @nosuchuser` returns `404`.

4.10 **/archive.** Body `/archive` from the channel owner returns `201` with `message` null and `channel.is_archived` true. A later normal post to the channel returns `423`.

4.11 **/unarchive.** Body `/unarchive` returns `201` with `message` null and `channel.is_archived` false. A normal post then works again.

4.12 **Same permissions as the routes.** A plain member who sends `/archive` gets `403` and the channel stays unarchived.

4.13 **Commands post nothing.** After rules 4.7 to 4.11 the channel's message list contains none of the command bodies.
