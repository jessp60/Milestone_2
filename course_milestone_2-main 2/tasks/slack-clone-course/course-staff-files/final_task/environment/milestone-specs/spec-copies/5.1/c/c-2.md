# C.2: reactions and direct messages

Routes covered: `POST /api/messages/{id}/reactions`, `DELETE /api/messages/{id}/reactions/{emoji}`, `POST /api/dms`.
Check: `bash /spec/c/checks/check_c_2.sh`. The rule numbers below match its output.

Do not start this spec until `check_c_1.sh` passes.

All routes are under `/api/...`, return JSON, and take `Authorization: Bearer <token>`. The three HTTP nodes listen on `127.0.0.1:8000`, `:8001` and `:8002`. Status codes unless a rule says otherwise: `200` on read/update success, `201` on create, `400` on validation, `401` on missing or invalid auth, `403` on auth-but-forbidden, `404` on unknown id, `409` on conflict, `413` on upload over limit, `423` on writes to an archived channel. Every request must answer within 5 seconds.

## Uses

Users, workspaces, channels, `POST /api/channels/{id}/messages` (returns `201 {message}`), `GET /api/channels/{id}/messages`, and `POST /api/channels/{id}/join`.

## Adds

| Function | What it does |
|---|---|
| reaction add and remove | keeps one reaction per (user, emoji) on a message |
| DM open | finds or creates the one DM channel between two users |

## Rules

`reactions` on a message is a list of `{emoji, count, user_ids}`, one entry per emoji.
In the URL of a `DELETE`, the emoji is percent-encoded (for example `%F0%9F%91%8D`).

2.1 **Add a reaction.** `POST /api/messages/{id}/reactions` with `{"emoji":"👍"}` returns `200` and `{reactions}` containing `{emoji:"👍", count:1, user_ids:[caller]}`, also on the first insert (not `201`).

2.2 **Idempotent.** Sending the same reaction again from the same user returns `200` and the same `reactions`, with `count` still `1`.

2.3 **Two users.** A second user adding the same emoji gives `count` 2 and both user ids in `user_ids`.

2.4 **Two emojis.** A different emoji on the same message becomes its own entry in `reactions`.

2.5 **Remove.** `DELETE /api/messages/{id}/reactions/{emoji}` returns `200` and `{reactions}` without the caller's id. Another user's reaction on the same emoji is still there with `count` 1.

2.6 **Remove the last one.** Removing the only reaction of an emoji removes that entry from `reactions`.

2.7 **Listing.** `GET /api/channels/{id}/messages` shows the current `reactions` on each message.

2.8 **Unknown message.** Adding a reaction to a message id that does not exist returns `404`.

2.9 **Missing emoji.** `POST /api/messages/{id}/reactions` with no `emoji` returns `400`.

2.10 **Auth on reactions.** `POST /api/messages/{id}/reactions` without a token returns `401`.

2.11 **Open a DM.** `POST /api/dms` with `{"user_id":<other user>}` returns `200` and `{channel_id}`.

2.12 **Same channel both ways.** The other user calling `POST /api/dms` with the first user's id returns the same `channel_id`.

2.13 **Repeated calls.** Calling `POST /api/dms` again with the same body returns the same `channel_id`.

2.14 **Unknown user.** `POST /api/dms` with a `user_id` that does not exist returns `404`.

2.15 **Talk in a DM.** Both users can post to the DM channel with `POST /api/channels/{channel_id}/messages` (`201`), and each sees both messages in `GET /api/channels/{channel_id}/messages`.

2.16 **DMs are private.** A third user who is not one of the two gets `403` when reading the messages of the DM channel.
