# C.3: files

Routes covered: `POST /api/files`, `GET /api/files/{id}`, `GET /api/files/{id}/download`, and `file_ids` on message posts.
Check: `bash /spec/c/checks/check_c_3.sh`. The rule numbers below match its output.

Do not start this spec until `check_c_2.sh` passes.

All routes are under `/api/...`, return JSON, and take `Authorization: Bearer <token>`. The three HTTP nodes listen on `127.0.0.1:8000`, `:8001` and `:8002`. Status codes unless a rule says otherwise: `200` on read/update success, `201` on create, `400` on validation, `401` on missing or invalid auth, `403` on auth-but-forbidden, `404` on unknown id, `409` on conflict, `413` on upload over limit, `423` on writes to an archived channel. Every request must answer within 5 seconds.

## Uses

Users, workspaces, channels and `POST /api/channels/{id}/messages`. A message has a `files` list.

## Adds

| Function | What it does |
|---|---|
| file store | keeps uploaded bytes and metadata, visible on all three nodes |
| attach | links a file to exactly one message |

## Rules

`FileObj = {id, uploader_id, filename, content_type, size, created_at}`.

3.1 **Upload.** `POST /api/files` as `multipart/form-data` with a `file` part returns `201` and `{file}` with every `FileObj` field. `filename`, `content_type` and `size` match what was sent, and `uploader_id` is the caller.

3.2 **Read metadata.** `GET /api/files/{id}` returns `200` and `{file}` with the same values, also when sent to another node.

3.3 **Unknown file.** `GET /api/files/{id}` for an id that does not exist returns `404`.

3.4 **Download bytes.** `GET /api/files/{id}/download` returns `200` with exactly the bytes that were uploaded.

3.5 **Download headers.** The download response has a `Content-Type` equal to the uploaded `content_type` and a `Content-Disposition` header that contains the filename.

3.6 **Download on another node.** The download works on a node other than the one that received the upload.

3.7 **Unknown download.** `GET /api/files/{id}/download` for an id that does not exist returns `404`.

3.8 **Size limit.** An upload of 10 MiB plus 1 byte returns `413`. An upload of exactly 10 MiB (10485760 bytes) returns `201`.

3.9 **Auth on upload.** `POST /api/files` without a token returns `401`.

3.10 **Missing file part.** `POST /api/files` as multipart with no `file` part returns `400`.

3.11 **Attach.** `POST /api/channels/{id}/messages` with `{"body":"here","file_ids":[<own file id>]}` returns `201` and `message.files` contains that file with its `FileObj` fields.

3.12 **Attached file in listings.** `GET /api/channels/{id}/messages` shows the file in `files` of that message.

3.13 **Not your file.** Attaching a file uploaded by another user returns `400`.

3.14 **Already attached.** Attaching a file that is already attached to a message returns `400`.

3.15 **Unknown file id.** Attaching a `file_ids` entry that does not exist returns `400`.

3.16 **Rejected attach posts nothing.** After a `400` from rules 3.13 to 3.15 no new message is in the channel.
