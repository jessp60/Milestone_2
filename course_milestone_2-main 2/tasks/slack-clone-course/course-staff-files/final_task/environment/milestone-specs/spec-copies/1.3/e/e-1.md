# E.1: editing and deleting messages

Routes covered: `PATCH /api/messages/{id}` and `DELETE /api/messages/{id}`, and their events.
Check: `bash /spec/e/checks/check_e_1.sh`. The rule numbers below match its output.

All routes are under `/api/...`, return JSON, and take `Authorization: Bearer <token>`. The three HTTP nodes listen on `127.0.0.1:8000`, `:8001` and `:8002`. Status codes unless a rule says otherwise: `200` on read/update success, `201` on create, `400` on validation, `401` on missing or invalid auth, `403` on auth-but-forbidden, `404` on unknown id, `409` on conflict, `413` on upload over limit, `423` on writes to an archived channel. Every request must answer within 5 seconds.

WebSocket: `ws://127.0.0.1:800x/api/ws?token=<bearer>`, one JSON frame per message. Client frames: `{"type":"subscribe","channel_id":N}` is answered with `subscribed` carrying `channel_id` and an integer `head_event_id`; `{"type":"resume","channel_id":N,"since_event_id":E}` replays every event after `E` in order and then sends `resumed` with `head_event_id` equal to the last event id. A new message is broadcast as `message.created` with `channel_id` and an integer `event_id`. Event ids in a channel are dense: the first is `head_event_id + 1`, then exactly +1 each, and every node shows the same ids.

## Uses

Users, workspaces, channels, `POST` and `GET /api/channels/{id}/messages`, reactions (`POST /api/messages/{id}/reactions`), and the WebSocket above.

## Adds

| Function | What it does |
|---|---|
| edit | changes a message body, author only, and records `edited_at` |
| delete | removes a message for the author or the workspace owner, idempotently |

## Rules

1.1 **Edit.** `PATCH /api/messages/{id}` with `{"body":"new text"}` from the author returns `200` and `{message}` with the new `body` and `edited_at` set.

1.2 **Timestamp.** `edited_at` is an RFC 3339 UTC string such as `2026-05-16T08:07:34.123Z`.

1.3 **Shared state.** The edit and `edited_at` show in the message listing on another node.

1.4 **Author only.** Neither the workspace owner nor another member can edit someone else's message: both get `403`.

1.5 **Auth.** `PATCH` without a token returns `401`.

1.6 **Unknown id.** `PATCH` on a message id that does not exist returns `404`.

1.7 **Validation.** `PATCH` with no `body` returns `400`.

1.8 **Delete.** `DELETE /api/messages/{id}` from the author returns `200` with `{"deleted":true}`.

1.9 **Gone from listings.** A deleted message disappears from `GET /api/channels/{id}/messages`. If you keep a tombstone instead, its `reactions` must be empty (reactions on a deleted message do not count).

1.10 **Idempotent.** `DELETE` on an already deleted message returns `200` with `{"deleted":true}` again.

1.11 **Edit after delete.** `PATCH` on a deleted message returns `409`.

1.12 **Owner.** The workspace owner can delete another user's message (`200`, `{"deleted":true}`).

1.13 **Others.** A member who is neither the author nor the workspace owner gets `403` on `DELETE`.

1.14 **Events.** Subscribers on every node receive `message.updated` for an edit and `message.deleted` for a delete. These events use the same dense `event_id` sequence as `message.created` (each advances it by exactly 1).
