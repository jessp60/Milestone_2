# D.2: the killed node comes back

Check: `bash /spec/d/checks/check_d_2.sh`. The rule numbers below match its output.
This check kills the node on port 8002 with `SIGKILL`.

All routes are under `/api/...`, return JSON, and take `Authorization: Bearer <token>`. The three HTTP nodes listen on `127.0.0.1:8000`, `:8001` and `:8002`. Status codes unless a rule says otherwise: `200` on read/update success, `201` on create, `400` on validation, `401` on missing or invalid auth, `403` on auth-but-forbidden, `404` on unknown id, `409` on conflict, `413` on upload over limit, `423` on writes to an archived channel. Every request must answer within 5 seconds.

WebSocket: `ws://127.0.0.1:800x/api/ws?token=<bearer>`, one JSON frame per message. Client frames: `{"type":"subscribe","channel_id":N}` is answered with `subscribed` carrying `channel_id` and an integer `head_event_id`; `{"type":"resume","channel_id":N,"since_event_id":E}` replays every event after `E` in order and then sends `resumed` with `head_event_id` equal to the last event id. A new message is broadcast as `message.created` with `channel_id` and an integer `event_id`. Event ids in a channel are dense: the first is `head_event_id + 1`, then exactly +1 each, and every node shows the same ids.

Important: the checks stop a process with `SIGKILL` by the PID that owns its port. Run each node as its own process that listens on exactly one of the ports `8000`, `8001`, `8002` (not one process that holds all three), so that killing one leaves the other two running. Never stop processes by name (`pkill -f`, `killall`, `pgrep -f`).

Do not start this spec until `check_d_1.sh` passes.

## Uses

Everything from D.1.

## Adds

| Function | What it does |
|---|---|
| respawn | `/app/start.sh` (or a watcher it starts) notices a dead node and starts it again without any outside help |
| catch-up | a respawned node serves the shared state, including what was written while it was down |

## Rules

The grading contract allows 60 seconds for a killed node to return. These checks allow 15 seconds so that they fit in a 30 second command.

2.1 **Respawn.** After the process that owns port 8002 is killed with `SIGKILL`, `GET /api/health` on port 8002 answers `200` with `node_id` 2 again within 15 seconds, without anyone starting it by hand.

2.2 **Survivors keep serving.** Nodes 0 and 1 answer `GET /api/health` the whole time node 2 is down.

2.3 **No data lost.** The respawned node returns the messages posted before the kill and the message posted on node 0 while it was down.

2.4 **Writes on the respawned node.** `POST /api/channels/{id}/messages` returns `201` on the respawned node and the message is visible on node 0.

2.5 **WebSocket on the respawned node.** A subscriber on the respawned node receives `message.created` for a post made on node 0, and the `event_id` values stay consecutive.

2.6 **Whole cluster.** All three nodes answer `GET /api/health` with their own `node_id` (0, 1, 2).
